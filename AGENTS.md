# Chewo — notes for agents

Conventions and gotchas discovered while working in this repo. Loaded into
every session via `@AGENTS.md` from `CLAUDE.md`.

## Learned

- 2026-07-18: Our umbrella term for one item in the tab bar is **"session"** (what you create/focus/close). Layers keep code-level names: **tab** = UI chip, **terminal** = `termId` pty runtime, **conversation** = `sessionId` CLI transcript. Vocabulary only — don't mass-rename identifiers unless asked.
- 2026-07-17, **reversed 2026-08-03**: Martin always runs multiple agents concurrently in the same repo, and never wants "you have 2 agents here" warnings — that part stands. What changed is the default: isolation *was* opt-in per terminal, and is now **on by default for every new agent session in a project**. The reason is Ship: a one-click `git add -A` in a shared checkout stages whatever every other live agent has touched, so the worktree is what makes shipping safe rather than a tidiness preference. It also removes the attribution work — `git status` in a worktree *is* that session's diff. Opting out is the branch menu's toggle. **Dev servers, the play button and the `+` shell still always stay in the main checkout** — they are not agent sessions.
- 2026-07-18: The UI/UX overhaul canon lives in `design/` — read `design/README.md` for the persona-pass process and `design/06-chosen-direction.md` for Martin's LOCKED visual direction. Direction is **Graphite base + Emerald accent** (the warm "Kiln"/terracotta values in `design/02–04` were rejected as "mustard brown"; 06 supersedes their hex, the token architecture in 04 still stands). HTML mockups in `design/mockups/`.
- 2026-07-19: For draggable UI (code tabs, cards), use native HTML5 DnD (`draggable` + `onDragStart`/`onDragOver`/`onDrop`/`onDragEnd`), matching `TodoBoard.tsx`. Critical gotcha: **never put `user-select: none` on the draggable element** — on this macOS Chromium/Electron it silently suppresses native drag initiation (element goes inert: no drag, no text selection). Native drag cancels text selection on its own, so it isn't needed. Dead ends that were tried and reverted: native DnD *with* `user-select: none` (cursor changes, nothing drags) and a pointer-events/`setPointerCapture` rewrite (highlights tab text instead of dragging).
- 2026-07-21: Second way to kill native drag in the same component: **never mount, unmount, or resize an element in the drag source's layout flow from `onDragStart`**. The T5 run strip rendered as `{draggingId && <strip/>}` above the columns — the state change reflowed the grid under the card mid-`dragstart` and the drag silently never began (symptom identical to the `user-select` bug: card feels inert). If such an affordance is ever needed again, keep it **always mounted and absolutely positioned**, toggling only `opacity`/`pointer-events`, which don't reflow — that fix worked, though the strip itself was then dropped for a modal button. Toggling a class on the dragged card itself (e.g. `.todo-card-dragging { opacity }`) is fine.
- 2026-07-29: **There is no Claude SDK in this repo** — no `@anthropic-ai/*` dependency exists. Every AI feature shells out to a CLI through `/bin/zsh -ilc`. The three headless ones (notes structuring, notes Q&A, todo voice) are **agent-agnostic**: pick the CLI per feature in Settings → Agents, stored in `userData/settings.json` under `agents`, read in main via `agentFor(task)`. **Add per-agent divergence only in `src/main/agent-runner.ts`** (`runAgentText` / `runAgentJson` / `chatCommand` / `normalizeChatEvent`) and describe the agent in `src/shared/agents.ts` — feature code must never branch on the agent. Gotchas that already bit: Codex's `--output-schema` is **OpenAI strict mode** (every property in `required`, `additionalProperties: false` — `toStrictSchema()` handles it) while Claude's `--json-schema` is looser; Codex emits whole `item.completed` messages, **not token deltas**, so `chat_text` carries a `delta` flag; Codex needs `--skip-git-repo-check` because the notes root and `~/.chewo` aren't repos. Never forward a CLI's raw event schema to the renderer — normalize to `ChatEvent` in main first. **Model lists are never hardcoded**: Claude uses its `--model` *aliases* (`opus`/`sonnet`/`haiku`/`fable`), which always resolve to the latest model of a tier; Codex is enumerated at runtime from `codex debug models` (`src/main/agent-models.ts`) because its catalog is server-driven and genuinely changes between calls. Reasoning effort is **per model, not per agent** — read it off the selected model, never a global list.
- 2026-07-29: **Interactive spawns are agent-agnostic too** — anything that launches a session (card runs, worktrees, new-session) must offer both CLIs, never hardcode `source: 'claude'`. Both take the prompt as a **positional argv** and auto-submit it (`claude [flags] '<prompt>'` / `codex [flags] '<prompt>'`); the divergence lives in `promptFlags()` in `src/main/terminals.ts` and is images only. Claude reads image *paths* found in the prompt, so it just needs the assets folder unlocked with `--add-dir`; **Codex has no read-side `--add-dir`** (its flag grants *write* roots) and its file tools can't read a PNG, so files are attached with `-i <file>` per image. Both flags are **variadic**, so the prompt always goes first and flags last — reversed, the CLI parses the prompt as another value and starts with no prompt at all.
- 2026-07-29: **Our MCP server is named `chewo`** (`packages/chewo-mcp`, package `@chewo/mcp`, tools reach models as `mcp__chewo__*`); the old `context-bridge` name survives only as `LEGACY_MCP_SERVER_NAME` for migration. It **ships inside the app** as an extraResource (`Resources/bin/chewo-mcp.cjs`) — never assume the user installs or registers it separately, and never register it with `node <path>`: Claude Code is a native binary and Codex is Rust, so a user can have both CLIs and no Node. The command is always **Chewo's own binary with `ELECTRON_RUN_AS_NODE=1`**. Registration is **opt-in in Settings → Connections**; `reconcileMcpServer()` at launch only repairs a registration the user already made (packaged builds only — in dev it would fight the installed app over the same config entries). Reads parse `~/.claude.json` / `~/.codex/config.toml` directly, **writes always shell out to `claude mcp add|remove` / `codex mcp add|remove`** (same doctrine as `mcp-writer.ts`). Server state is `~/.chewo/mcp/` (inbox + audit.log). Renderer-safe names/types live in `src/shared/chewo-mcp.ts`, fs paths in `src/shared/mcp-paths.ts` — keep node imports out of the former.
- 2026-07-29: **Dictation streams to Deepgram; the Swift sidecar is capture-only.** `packages/audio-capture` (`chewo-audio-capture`) opens the mic or a Core Audio process tap and writes **16 kHz mono Int16 to fd 3** — nothing else. It has no package dependencies and knows nothing about transcription. Main owns the Deepgram connection (`src/main/deepgram.ts`, `listen.v1`), so the API key never reaches the renderer; it lives in `userData/credentials.json` encrypted via Electron `safeStorage` (`src/main/credentials.ts`), deliberately **not** in `settings.json`, which the renderer rewrites wholesale. Traps that already bit: **WebSocket booleans must be strings** (`interim_results: 'true'`) while the *batch* endpoint takes real booleans; **`stopped` is emitted only after the sidecar drains fd 3**, so it means "audio complete" and is what lets main close the stream without clipping words; **`nova-3` is a wire alias Deepgram accepts but never lists** in `GET /v1/models` (the catalog says `nova-3-general`), and storing an unlisted id left the picker with no matching row, which silently drifted the user's model — `normalizeStt` migrates the aliases, and **`Select` must never fall back to `options[0]`** when the value is missing or it displays a setting the user never chose. The model picker offers **two curated tiers**, not the catalog's 41 models across ~400 rows (one row per model *version*, which also handed React duplicate keys and broke filtering): Nova-3 monolingual ($0.0048/min) and multilingual ($0.0058/min), the latter being the *same* `nova-3-general` with `language=multi`. Flux is excluded — it needs `listen.v2` and a different message protocol. Every capture is also written to `userData/recordings/<id>.pcm` **synchronously** (a buffered stream loses its buffer when the app dies, which is the exact case the file exists for); a clean `final` deletes it, anything else leaves it recoverable via 5-minute WAV chunks through the pre-recorded API.
- 2026-07-29: **`npm install <package>` breaks terminals; `npm install` with no args does not.** npm strips the executable bit off files inside a package (it only preserves it for declared `bin` entries), and node-pty's prebuilt `spawn-helper` needs it — without it `terminal:create` dies with `posix_spawnp failed`. The repo's root `postinstall` (`chmod +x node_modules/node-pty/prebuilds/*/spawn-helper`) repairs this, but it **only runs on a bare `npm install`**. A targeted `npm install <pkg>` re-extracts node-pty, re-strips the bit, and skips the root `postinstall` — verified both ways, including an install that reported "up to date" and still broke it. **After adding any dependency, run `npm run postinstall`.**
- 2026-07-29: **A missing runtime dependency produces a build that succeeds and an app that dies on launch.** electron-vite leaves `dependencies` as bare `import`s in `out/main/index.js` (it never bundles or resolves them), and electron-builder copies prod deps out of `node_modules` — so a package listed in `package.json`/`package-lock.json` but absent from `node_modules` is silently skipped by *both*, and the packaged app throws `ERR_MODULE_NOT_FOUND` at startup. This is what a pull that adds a dep looks like when `npm install` wasn't re-run (it bit `@deepgram/sdk` after the Deepgram merge). **Run `npm install` after any pull/merge that touches `package.json`**, and if a packaged build reports a missing module, check `node_modules/<pkg>` before suspecting the packaging config.
- 2026-07-29: **Worktree truth comes from git, not from `projects.json`.** The sidebar's "Isolated branches" group is reconciled against `git worktree list --porcelain` (`listWorktrees` in `src/main/worktrees.ts`), because the records drift: dev and packaged builds keep **separate** `projects.json` files, and closing a pane deletes the `SavedTerminal` that was the branch's only handle. Two gotchas if you touch this. (1) **"0 commits ahead of main" cannot tell a fresh worktree from a merged one** — both sit at zero. Anything that decides a branch is done must compare the tip against the commit it was *cut at* (`Worktree.baseCommit`, recorded at creation, recovered from the branch reflog's `branch: Created from X` entry when adopting), and must treat unknown provenance as still-live: locking a fresh worktree is far worse than leaving a spent one open. Uncommitted changes always keep a branch live. A squash/rebase merge rewrites SHAs and is deliberately *not* detected — the merge modal's **Mark as done** sets `Worktree.doneAt`, the hand override for exactly that, undoable from the row. (2) The `Row` primitive (`components/ui/Row.tsx`) **paints its own live dot** from the `live` prop — passing a `<Dot tone="live"/>` as `leading` renders a second one.
- 2026-07-29: **`git status` collapses a wholly-untracked directory into one entry with a trailing slash** (`? packages/foo/`), so a status entry is not always a file. Diffing one is a trap: `git diff --no-index -- /dev/null <dir>/` resolves `/dev/null`'s *basename* inside the directory and dies with `error: Could not access '<dir>/null'` — the panel's "Could not access …/null" bug. `ChangedFile.isDir` now flags these, `gitDiff` refuses them, and `GitPanel` expands the row via `gitUntrackedFiles()` (`git ls-files --others --exclude-standard`, capped at 500). **Do not "fix" this by switching status to `-uall`** — one unignored build dir turns 1 row into 517 (measured on this repo against a stale 318 MB Swift `.build/`, since deleted).
- 2026-07-30, **narrowed 2026-08-03**: **`src/main/git.ts` is read-only by contract; every git *mutation* lives elsewhere, split by blast radius** — `git-ops.ts` (bring commits in), `git-ship.ts` (send work out), `worktrees.ts` (checkout lifecycle). Keep that split so "does this touch the repo?" is answerable by filename. Same house rules everywhere: never `--force`, never `-D`, never stash, and pass git's own message through verbatim. **`git-ops.ts` was a whole branch menu — list/switch/create/fetch/pull/push — and all of it went when sessions became worktrees**: you don't switch branches in a session's checkout (you start another session), push is Ship's job, and fetch only existed to serve those two. What is left is `gitUpdateFromBase`, and the reason it is not called Pull is load-bearing: **a task branch has no upstream, so `git pull` in a worktree fails with `no upstream configured for branch 'agent/foo'`** — verified. It fetches, then fast-forwards when HEAD *is* the default branch (several agents share the main checkout; a merge there is a conflict resolution nobody asked for) and merges `origin/<default>` in otherwise. Merge not rebase, because Ship pushes early and rebasing a pushed branch means a force-push. A conflict is aborted so an agent never finds its checkout mid-merge. `defaultRemoteRef` reads `refs/remotes/origin/HEAD` — **no network**, which is what lets the worktree-creation path use it — falling back to main/master/trunk/develop for repos made with `git init` rather than cloned, where that symref does not exist.
- 2026-07-30: **Cleanup after a merge is a preference, never new git logic.** The merge modal's auto-cleanup (`SettingsFile.worktrees.autoCleanupOnMerge`, default on, mirrored by the footer checkbox) calls the same `removeWorktree()` the button calls — unforced `git worktree remove` + `branch -d`. Keep it that way: the safety is that **git refuses**, not that we checked first, so anything tempted to add `--force`/`-D` here is removing the only guard. Three things that shape the UI and are easy to get wrong if you touch it. (1) A cleanup refusal is **not a merge failure** — the commits are on the target regardless, so it renders in its own `cleanupError` warning banner ("Merged, but the worktree was kept") and never in `error`, which means the merge came apart. (2) On success `onRemove()` unmounts the modal (App drops the worktree record), so the merge handler must **return before touching state** rather than falling through to `setBusy`/`refresh` on a dead component. (3) The checkbox is the consent, so auto-cleanup deliberately does **not** re-prompt; only the manual "Remove worktree…" button confirms. Unrelated trap found next door: `AppSettings`' footer reset ran `onChange(DEFAULT_APPEARANCE)` for every pane that wasn't `agents`, so each new feature pane silently shipped a button that discards the user's theme — it is pane-aware now, and a new pane must extend `reset`/`resetLabel`.
- 2026-07-30: **Distribution is build-from-source on purpose, and the packaging tolerates a missing sidecar.** The app is ad-hoc signed (`identity: null`), so a *locally built* app opens cleanly while the same bundle moved over any network gets `com.apple.quarantine` and macOS rejects an ad-hoc-signed quarantined app with **"Chewo is damaged and can't be opened"** — not the softer "unidentified developer" prompt. That's why the README sends people to `npm run dist:install` rather than a download; `npm run dist:zip` exists for handing someone a build, and it always needs `xattr -dr com.apple.quarantine` on the other end. Only a Developer ID cert + notarization actually fixes this. Two things that make a first build survive: (1) `ensure:stt` is `--soft` everywhere now (`predev`, `predist`, `predist:zip`) because **electron-builder logs `file source doesn't exist` and skips a missing `extraResources` entry rather than failing** (`copyFiles` in `app-builder-lib/out/fileMatcher.js`) — verified by building with the sidecar moved aside, which produced a working app with only `chewo-mcp.cjs` in `Resources/bin/`. So no Swift toolchain costs you dictation, not the build. (2) `dist:install` is `scripts/install-app.mjs`, not a `ditto` one-liner: electron-builder names its output dir per arch (`mac-arm64` vs `mac`), and it refuses to copy over a **running** Chewo, which otherwise leaves a half-replaced bundle that crashes on next launch.
- 2026-07-30: **Never hand-edit a `version` field — releases go through `npm version <patch|minor|major>`.** That one command bumps the root, runs `scripts/sync-version.mjs` from the `version` lifecycle hook to propagate the number into every workspace package, stages them, and lets npm make **one** commit and tag covering all of it; `preversion` gates on `typecheck` + `test`, `postversion` pushes `main --follow-tags`. The `version` hook (not `postversion`) is load-bearing: it fires after the root bump but before the commit, which is the only window where staged files still land inside the tagged commit. `sync-version.mjs` hardcodes its workspace list — extend it when `packages/*` grows. Also worth knowing before adding version ceremony: **semver is not how Chewo identifies a build.** `src/main/app-version.ts` stamps each build with its git commit (`__BUILD_HASH__` from `electron.vite.config.ts`), diffs it against repo HEAD, and drives the sidebar's "behind by N commits" + rebuild CTA — so the version field only surfaces in the .app's Get Info panel and electron-builder artifact names.
- 2026-08-02: **Chat panes and terminal panes are two runtimes for one thing, sharing one id space.** A `TerminalTab.mode` of `'chat'` drives the agent over JSON (`src/main/chat-sessions.ts` → `ChatPane`); `'terminal'` is the pty. Ids come from `src/main/pane-ids.ts` so the tab strip, drag/drop, `paneTabs` and `MainView` never learn the difference — which is also what lets a conversation move between the two by killing one and `--resume`-ing the same `sessionId` in the other. **The terminal is not going away**: shell panes (`npm run dev`, worktree setup, the play button) are ptys forever, so "replace the TUI" would delete the fallback while keeping all the machinery. **Removed 2026-08-03: the chat pane's header** (agent badge, model, cwd, and the "Terminal" button that handed a conversation to a pty). The cwd duplicated the tab's ⎇ label and the branch chip, and a whole bar's height for an escape hatch that was never used did not earn it. `openInTerminal` went with it — the `--resume` ids still line up, so the swap is a caller away, but there is no UI for it and `claude auth` / an interactive `/config` / a broken wire format now need a shell pane. Four things about the Claude wire format cost real time to find, all verified against CLI 2.1.220 by `npm run canary:chat` (run it after every CLI update): (1) **`--permission-prompt-tool stdio` is undocumented** — absent from `claude --help` — and it is the *only* way to get permission prompts as `can_use_tool` control requests; `--permission-mode manual` just fails the tool with "you haven't granted it yet" and never asks. (2) Echoing the CLI's own `permission_suggestions` back as `updatedPermissions` is what makes "always allow" stick, so the CLI owns that state and we keep no shadow allowlist. (3) **Assistant text arrives by two routes** — as `stream_event` deltas *and* again in the completed `assistant` message — except locally-handled slash commands (`/context`), which only ever produce the `assistant` message; rendering both duplicates every reply, rendering one loses half, so `claude-chat.ts` tracks which message ids streamed. Block indices restart at 0 per message, so block ids must be `messageId:index`. (4) **`system/init` is withheld until the first turn begins**, so a fresh pane has no model and no slash commands until you have already sent something — the fix is the SDK-style `initialize` control request at spawn, which returns the full command catalog immediately. Related trap: `createChat` returns through IPC *before* the renderer mounts the pane, so nothing may be emitted synchronously from it (that event has no listener yet) — spawn-time facts like cwd reach `ChatPane` as props.
- 2026-08-02: **Whether a thinking block has readable text is per-model, and streaming cadence needs smoothing.** Verified 2026-08-02: haiku streams reasoning as `thinking_delta`s, but **opus emits the thinking block and a `signature_delta` and nothing else** — zero deltas, zero characters in the final `assistant` echo, because the reasoning is encrypted. So a thinking disclosure must check for text before offering a chevron, or it opens onto nothing (`chat-thinking-head--static` in `ChatItems.tsx`). Two neighbouring UI facts. (1) The CLI reports an **interrupted turn exactly like a failed one** (`result` with `is_error`), so `chat-sessions.ts` sets a `interrupted` flag in `interruptChat` and stamps `stats.cancelled` on the turn it stops — otherwise stopping on purpose reads as "The turn ended with an error". A tool in flight when a turn ends never receives its `tool_result`, so `reduceChat` settles any still-`running`/`awaiting` chip to `cancelled` or it spins forever. (2) Model text arrives in bursts of roughly a clause, which reads as stuttering; `useSmoothText` reveals it a few characters per frame with the step derived from the backlog, so it always catches up and never becomes the bottleneck. It snaps to full text under `prefers-reduced-motion` **and when the page is not visible** — Chromium throttles rAF for hidden windows, which would otherwise leave text stranded behind. The streaming caret is appended to the markdown *source*; as a sibling element it lands after the trailing `<p>` and sits on its own line.
- 2026-08-02: **Resuming replays nothing, and the transcript parser was silently truncating long sessions.** `claude --resume <id>` loads the conversation into the CLI's own context and then stays quiet until the next turn — no history crosses the wire — so a resumed chat pane opens blank. It is seeded from disk instead (`seedItems` in `agent-chat.ts`, fed by the same `getSession` parse the transcript view uses), from `TerminalTab.resumeSessionId` — deliberately *not* `sessionId`, which a fresh pane fills in itself and would make every live message render twice. Finding that exposed a **pre-existing adapter bug**: `parseClaudeSession` linearised by walking `parentUuid` from the newest record, but compaction and summary boundaries re-point or drop that link, and *every boundary severs the chain*. On a real long session, 964 main records yielded a **16-record chain across 58 breaks** — so both the chat pane and `TranscriptView` showed the last handful of messages and nothing else, while `meta.messageCount` (computed over the whole timeline, so unaffected) cheerfully said 488. The parse now uses the chain only when it actually reaches the first record and otherwise falls back to append order, trading rewind-branch pruning for completeness in exactly the case where the links are too broken to prune by; `tests/fixtures/claude/v2.1-compacted.jsonl` pins it. Related: the CLI withholds `system/init` until the first turn, so a pane's **model is unknown until the user speaks** — the header shows nothing rather than an indefinite "Starting…", which reads as a pane that never loaded, and the "Terminal" escape hatch falls back to the resume id so it is not dead on a resumed pane.
- 2026-08-02: **Clicking a session in the sidebar resumes it — there is no read-only transcript any more.** `TranscriptView` is deleted; `openSession` focuses the existing pane if the session is already running, otherwise calls `resumeSession`, which opens a chat pane seeded with the history. A running session's row is **dimmed** (`.session-row--running`) rather than disabled, because the useful action is still "focus that pane" — what must never happen is a second process starting on a conversation that is already live, which interleaves the file and makes the next resume pick the wrong branch. Find-in-conversation moved with it: `components/chat/FindBar.tsx` keeps ⌘F, and it paints matches with the **CSS Custom Highlight API** rather than wrapping text in `<mark>`s — the thread is live markdown that re-renders on every token, so mutating it to insert elements would fight the reconciler; ranges over text nodes survive re-render. Its Escape handler is registered in the **capture** phase so closing the find bar does not also fire the pane's Escape-to-interrupt. Two classes survive the deletion and must not be swept up as dead: `.message-markdown` (the chat thread uses it, so a live reply and a re-read one look identical) and `.transcript-error` / `.transcript-loading` (reused by `CapabilitiesView`). Open perf question, not yet a bug: a resumed pane renders every message — 539 items and ~29,000px on a real session — so a long conversation will want virtualisation before this grows.
- 2026-08-02: **A resumed pane renders one page and grows upward; the tab bar's `+` is a shell, nothing else.** Seeding a long conversation whole cost ~29,000px of DOM (539 items), so `ChatPane` withholds all but the last `PAGE` (50) and pulls earlier ones in as the user scrolls near the top — 51 items and ~2,800px on the same session. The window is tracked as a **`hidden` count from the front**, not a visible count: new items append at the end and are always shown, so nothing scrolls out of view above while the agent is talking. Two scroll subtleties, both bugs before they were fixed. (1) Prepending pushes content down, so the restore anchors on the distance from the *bottom*, and that effect is declared **before** the recorder so it consumes the gap measured on the previous render. (2) Pinning to the bottom only when items change is not enough — **markdown finishes laying out after that effect runs**, growing the scroll height underneath it and leaving a resumed pane a screen short of the newest message; the pin re-asserts on *every* render instead, which also follows the stream. ⌘F expands the window to everything first (`FindBar`'s `onOpen`), because find walks the DOM and would otherwise silently search one page. Separately, the `+` in the tab bar creates a shell directly — no menu. Agents are created from the sidebar's "New session", which already offers both CLIs, and having two launchers meant two things to keep in sync.
- 2026-08-03: **Three mutating git files now, split by blast radius: `git.ts` (read-only) → `git-ops.ts` (branch/remote) → `git-ship.ts` (commit + push + `gh pr create`).** Ship is one click with no prompts, so every decision it would ask about is a rule instead: base is the repo's own default branch (`gh repo view --json defaultBranchRef`, never a hardcoded `main`), the message comes from `git-text.ts`, and **shipping from the default branch cuts a branch first** rather than refusing — `git add -A` runs *before* the branch decision on purpose, because `git switch -c` carries the index across, which makes one `git diff --cached` the single source of truth for both the commit message and the generated branch name. Everything is idempotent: a second click pushes onto the PR the first opened (`gh pr list --head`), and a clean tree with nothing ahead says "nothing to ship". Two traps. (1) **`gh` is a Homebrew binary and Electron's PATH is not the login shell's** — the path is resolved once through `/bin/zsh -ilc 'command -v gh'` and then `execFile`d directly, so a PR body full of backticks needs no escaping; running gh *through* a shell would. (2) A failed `gh pr create` is not automatically a failed ship — the push already landed, so it re-checks for an existing PR before reporting an error.
- 2026-08-03: **Agent-written git prose lives in `git-text.ts` and is never allowed to block — but branch names are not prose.** Commit messages and PR text go through `runAgentJson` under the new `gitText` `AgentTask` (agent-agnostic, picked in Settings → Agents), each with a 25 s timeout and a **deterministic local fallback**, because a CLI mid-update must never be why a change can't ship. Branch naming was tried this way and **removed**: measured against the real CLI, "test" came back as `{"name":"test"}` — identical to the regex — for a second of latency and a spawn. It is now `src/shared/branch-names.ts` (`slugifyBranch` → `uniqueBranchName` → `branchNameFor`), pure, shared by the renderer and `git-ship.ts`, and it also sanitises: `../../etc/passwd` collapses to `etc-passwd`, never a traversal, since the result is both an argv element and a directory name. **The trap that made this visible: a headless `claude -p` writes a session file keyed on its cwd, and `assignProject` files sessions into the sidebar by that path — so running one in the repo it describes puts a "Name a git branch after this task" row in that project's session list.** Every headless feature therefore pins its cwd *outside* the user's repos (`todo-voice` → `~/.chewo/todos`, notes → the notes root, `git-text` → `~/.chewo/git-text`); Home only lists `s.project === homeDir` exactly, so `~/.chewo/*` shows nowhere. Testing gotcha that cost time: **`vi.fn().mockRejectedValue` / `mockImplementation(async () => { throw })` reports a rejection these functions deliberately swallow as an *unhandled* one**, failing the test after its assertions passed — mock the runner with a plain mutable `let answer: () => Promise<unknown>` instead of a `vi.fn()`.
- 2026-08-03: **A worktree per agent session is cheap here, and `node_modules` is the only part that isn't free.** Measured on this repo: `git worktree add` is **0.08 s** (194 tracked files, `.git` is shared so there is no second 179 MB), and `cp -cRp node_modules` is **8.2 s for 0 MB of real disk** — `-c` is an APFS clone, so it is copy-on-write and syscall-bound on ~30k files rather than on the 667 MB. `cloneNodeModules` in `worktrees.ts` runs **fire-and-forget** from the `worktree:create` handler: the pane opens the instant the checkout exists and the dependencies land while the user is still typing, which works because an agent reads code for several seconds before it runs anything. `-p` is load-bearing beyond timestamps — it preserves the **exec bit**, so a cloned `node_modules` sidesteps the npm-strips-`spawn-helper` trap that the root `postinstall` exists to repair. Failure is non-fatal by design (no `node_modules`, non-APFS volume): it toasts and the agent runs `npm install` like it would have anyway.
- 2026-08-03: **Merging into the local main checkout is gone — Ship is the only way work lands, and it goes through a review.** `mergeWorktree`, `worktreeStatus`, `landingBranchFor`, their IPC, `WorktreeMergeModal`, the `autoCleanupOnMerge` setting and the whole Settings → Worktrees tab were all deleted. Why: it bypassed review, it **never pushed** (so local main silently drifted from origin, which the origin-based worktree cutting then propagated to every new session), and its cleanup checkbox was a second mechanism for the job the merged-PR reaper already does. `worktreeState`'s "this branch is spent" detection stays — git still has to recognise a landed branch however it landed, and the test harness now lands one with a plain `git merge` rather than through the app. **`ShipModal` replaced it**, reached from the tab-bar Ship button (the focused checkout) and the sidebar worktree row (a branch with no pane open — the only case the tab bar can't cover; the per-tab icon was dropped as redundant, since clicking a tab focuses it). It keeps "Mark as done" and "Remove worktree…" in its footer. Two rules hold it together. (1) **`shipPreview` has no side effects** — it must not stage, commit or push, because it is what you read before agreeing; the cost is that its commit message is written from `git diff HEAD` plus untracked *names* rather than a staged diff, which is the right trade against leaving a cancelled review's changes staged. (2) The agent is asked **in the preview**, and `shipPullRequest` takes the confirmed `message`/`pr` as arguments, so pressing Ship is one commit, one push, one `gh pr create` with no model call in between. (3) **The wait lives on the Ship button, not in the dialog** — App reads the preview first and mounts `ShipModal` only with a finished one, because a modal that opens onto "Reading the change…" is a modal that opened too early. The read itself was the real problem: `gh repo view`, `gh pr list` and `git status` now run concurrently, and **a branch with no prior commits skips the PR-text call entirely** (its PR title *is* the one commit's subject, so asking a model to paraphrase text we already have was a second CLI spawn for nothing) — which is the common case, since every session cuts a fresh worktree. `git status --porcelain -uall` is used here deliberately (the panel's `-unormal` collapses an untracked directory to one row, which hides how much is about to be committed — the opposite of what a review needs).
- 2026-08-03: **Isolation is cut on the first message, not at spawn — and merged worktrees reap themselves.** A new agent session in a project defaults to `TerminalTab.branchMode: 'separate'`, but nothing is created at spawn: the worktree is named after the task, and there is nothing to name it until the user has spoken. `ChatPane`'s `beforeFirstSend` hands that first message to App, which slugs a name, cuts the worktree and **replaces the pane in place** (`replacePane`) with one whose `initialPrompt` is that same text. Four things this depends on. (1) The choice is offered **only until `sessionId` exists** — the honest "this session has started" signal for a chat pane, since the CLI only announces itself on the first turn; moving a live agent between checkouts is a different, manual act. (2) `beforeFirstSend` returning true is a promise to handle the message, so **both** outcomes end in a replacement pane — a worktree that can't be cut lands the session back in the main checkout with the reason in a toast, and no typed message is ever dropped. (3) *Superseded* — a pty pane used to have no composer to intercept, so the New session menu collected the task inline; a Codex session is now typed in a chat pane and swaps to a pty on send. (4) `cutWorktree` is the only thing that mints a `Worktree`, shared by the create modal and this path. Reaping (`reapMerged`) runs on window focus, throttled to 5 minutes, off **one** batched `gh pr list --state merged --json headRefName` per project — a call per worktree would tax every focus. Three rules make it safe to let it delete checkouts: it calls the same unforced `removeWorktree` (so **git refuses** anything unmerged or dirty), it **never touches a worktree with a live pane** (removal kills panes, and a checkout vanishing under a running agent is worse than an extra folder), and `mergedBranches` returns `[]` when gh is unreachable, so a network failure reaps nothing rather than everything. The throttle stamp is set only once there is something to ask about — worktrees load a beat after first render, and an empty first pass would otherwise spend the window.
- 2026-08-03: **A session is created undecided, and nothing is spawned until the first message.** `selectSection` opens an unstarted pane when the section has no tabs, and the sidebar's "New session" does the same; the menu that used to ask for the agent and the checkout up front is gone, and so is `startIsolatedNow`. An unstarted pane is `TerminalTab.pending`: a real tab with a composer and **no process behind it**, whose id comes from `pane:reserve` (the same `nextPaneId` counter, so the pane it becomes can take its place in the strip). Everything the setup row asks — agent, model, effort, checkout — is only answerable once you know the task, and a CLI spawned before those were settled would have to be killed and respawned on each change; `startChosenSession` builds the real pane on the first message and always returns true for a pending tab. Consequences worth knowing. (1) Choosing Codex is a runtime swap into a pty, which is why the old "a pty has no composer, so the menu collects the task inline" special case could go. (2) A pending pane has **no slash-command palette** — the catalog comes from the spawned CLI's `initialize`, so it arrives with the real pane. (3) Pending tabs are never persisted: `savedFor` filters on `!!t.sessionId`. (4) `killPane` on a pending tab calls `chatKill` for an id main has never seen, which is a deliberate no-op.
- 2026-08-03: **Interactive sessions open on the best model at high effort, and neither default names a dated id.** `NEW_SESSION_DEFAULTS` in `shared/agents.ts` is Claude → `opus`, Codex → the **head of its own discovered catalog** (`codex debug models` is priority-ordered, so entry 0 is the CLI's "latest frontier" slot — `gpt-5.6-sol` today), both at effort `high`. Deliberately *not* `AgentDef.defaultModel`, which stays "let the CLI decide" for the headless features. `sessionModel`/`sessionEffort` are the single resolver used by both the composer's picker and the spawn, so a session can never run on a model the row was not showing; effort is **clamped to the model's own `efforts`** because the set is per model (gpt-5.5 has no `max`, gpt-5.6-sol adds `ultra`) and an unaccepted level fails at spawn. `TerminalTab.model`/`effort` hold the user's override only — absent means "resolve", so a CLI update that renames a model doesn't strand a tab. Switching agent clears both (a model id belongs to one catalog). The flags diverge in `modelFlags` (`src/main/terminals.ts`): claude takes `--model`/`--effort`, **codex has no effort flag** and takes `-c model_reasoning_effort="…"`. Both values are `shellQuote`d rather than validated against an enum the way `permissionFlag` is — the accepted set is discovered at runtime, so quoting is the only guard that a catalog string reaches the command line as exactly one argument.
- 2026-08-03: **An unstarted isolated pane must not wear the shared checkout's branch.** It has no checkout of its own until its first message, so it sits in the project's main checkout — and that checkout is on whatever branch you last left it on, which is *not* this session's. Reporting it made every new session look like it had inherited an old branch (the bug that prompted all of this). `pendingBase` in App drives a dashed `.branch-chip--pending` reading "new branch · from origin/main" instead, and **Update and Ship are hidden** while it is set: both would act on a checkout the pane is only borrowing. What is deliberately *not* done is switching the shared checkout to the default branch — dev servers, the play button and every other pane are standing on it, and it fails outright when dirty. The file tree and git panel do still show that checkout's files; that is honest, since it is what is on disk there. Selecting a project also runs `gitFetchRemote` (throttled 5 min per path, fire-and-forget) — a session is cut from `origin/<default>`, so "start current" is exactly a fetch and nothing that moves a ref any checkout stands on. `git:default-base` names the base for the UI and costs nothing (local symref).

- 2026-08-03: **The in-app Update quits before it installs — `dist:install` can never run from inside the app.** `runSelfUpdate` used to shell `npm run dist:install`, whose last step is `scripts/install-app.mjs`, which dies on `pgrep -x Chewo` ("Chewo is running — quit it"). The updater *is* Chewo, so the button burned a full electron-builder run and then failed, every time, with the reason visible only in the footer's `title` tooltip. It now runs `npm run dist` and hands the swap to a **detached** `install-app.mjs --wait-for <pid> --reopen` (`detached: true` + `unref()`, output appended to `~/.chewo/update.log` — the only record once the app is gone), then `app.exit(0)` with **no `app.relaunch()`**: the helper reopens the new bundle after the swap, and relaunching here would race it into the old one. Three things the helper has to get right. (1) `pgrep -x Chewo` **also matches Electron's own GPU and utility children** — they exec the same `Contents/MacOS/Chewo` binary — so the post-exit check polls for up to 20 s instead of failing on the first read, which would abort good updates at random. (2) The copy is **staged** (`ditto` → `Chewo.app.incoming`, `mv` target → `.previous`, `mv` staged → target, restoring on failure): the slow failure-prone step happens while the installed app is still intact, and the swap is two same-volume renames. (3) `--reopen` also fires from `die()`, because a failure that happens *after* the app quit must still put something on screen. Unrelated but worth not chasing: `codesign -v --deep --strict` reports "code has no resources but signature indicates they must be present" on the installed app *and* the fresh `dist/` build — pre-existing `identity: null` ad-hoc signing, not something the swap introduces.

- 2026-08-03: **A branch cut from a remote-tracking ref inherits *that* branch as its upstream, which is what broke Ship.** `git worktree add -b agent/foo <dir> origin/main` leaves `branch.agent/foo.merge = refs/heads/main` (git's default `autoSetupMerge` fires on a remote-tracking start point), so `git status` in the session reports against a branch it is not, and Ship's bare `git push` dies with **"fatal: The upstream branch of your current branch does not match the name of your current branch"** — on *every* worktree session, after the commit had already landed. Two-sided fix, and both sides are load-bearing. (1) `createWorktree` passes **`--no-track`**, so a task branch genuinely has no upstream until Ship gives it one — which is what the comments in `BranchChip.tsx` and `git-ops.ts` had been asserting all along, and were wrong about. (2) `git-ship.ts` no longer treats "`@{u}` resolves" as "this branch has *its own* upstream": `tracksOwnBranch` compares `branch.<name>.merge` against `refs/heads/<name>`, and anything else falls through to `push --set-upstream`, which both pushes and repoints. That second half is not belt-and-braces — it is what repairs the worktrees created before the fix, so no migration was needed.
